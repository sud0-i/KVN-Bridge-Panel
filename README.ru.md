# KVN-Bridge-Panel

[English](README.md) · **Русский**

[![CI](https://github.com/sud0-i/KVN-Bridge-Panel/actions/workflows/ci.yml/badge.svg)](https://github.com/sud0-i/KVN-Bridge-Panel/actions/workflows/ci.yml)
[![License: AGPL-3.0](https://img.shields.io/badge/license-AGPL--3.0-blue.svg)](LICENSE)

Панель для своего VPN на своих серверах — для себя, семьи и друзей. Ставится одной командой,
дальше всё делается из браузера: серверы добавляются по IP и root-паролю, пользователи получают
ссылку на подписку и подключаются из привычных приложений.

Главная идея — **каскад**: пользователи подключаются к «мосту» (обычно в своей стране), а в интернет
трафик выходит через «выходную ноду» за рубежом. Так соединение до моста выглядит как обычный
трафик внутри страны, а выходных нод может быть несколько. Подходит и для одного сервера без каскада.

```
устройство ──▶ мост ──▶ выходная нода ──▶ интернет
                              └──▶ Cloudflare WARP (по правилам)
```

## Возможности

- **Протоколы:** VLESS + Reality (основной), XHTTP, Hysteria2, mieru и подключение через CDN
  (Cloudflare). Каждый включается переключателем; пользователи получают все варианты в одной
  подписке и переключаются, если один из них начнут блокировать.
- **Каскад и отказоустойчивость:** мост распределяет трафик между выходными нодами и убирает
  упавшие. Если упали все, трафик блокируется, а не уходит с IP моста.
- **Установка нод из панели:** IP и root-пароль — остальное (Xray, агент, фаервол, сетевой тюнинг,
  WARP) ставится само. Ноды сами обновляют агент, Xray и геобазы.
- **Маршрутизация:** местные сайты напрямую, отдельные сервисы через Cloudflare WARP, свои правила.
- **Пользователи:** квоты трафика, сроки, страница подписки с инструкцией и кнопками «Скачать» /
  «Добавить», импорт пользователей вместе со старыми ссылками из другой панели.
- **Мониторинг:** нагрузка серверов (CPU, память, диск, сеть, steal, потери пакетов), качество канала
  мост → выходная нода, графики за сутки и неделю.
- **Уведомления в Telegram:** нода пропала, канал деградировал, у пользователя кончается трафик или
  подписка. Работает и там, где Telegram заблокирован.
- **Управление серверами:** перезапуск служб и перезагрузка, терминал прямо в браузере, вход на
  серверы только по ключу.
- **Безопасность:** панель по секретному адресу, двухфакторный вход, у каждой ноды свой токен и ключ,
  ежедневные бэкапы.
- Интерфейс на русском и английском, удобен с телефона.

## Что нужно

- **Сервер для панели** с Debian или Ubuntu (x86-64), от 1 ГБ памяти, и домен (или поддомен),
  направленный на него A-записью. Порты 80 и 443.
- **Серверы для нод** (по желанию) — тоже Debian или Ubuntu x86-64 с root-доступом по SSH.
  Мост лучше арендовать в своей стране, выходную ноду — за рубежом.
- Панель и мост могут жить на одном сервере, а для начала хватит вообще одного сервера.

## Быстрый старт

1. Направьте домен на сервер и запустите установщик:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/sud0-i/KVN-Bridge-Panel/main/install.sh | sudo bash
   ```
   Он поставит Docker, спросит домен, пароль администратора и нужно ли сделать этот же сервер
   мостом, а в конце покажет адрес панели.
2. Откройте панель и включите двухфакторный вход: «Настройки» → «Двухфакторный вход».
3. **Ноды** → «Добавить ноду»: IP, роль (мост или выходная нода) и root-пароль. Через 2–3 минуты
   нода появится в списке.
4. **Пользователи** → «Добавить». Кнопка 🔗 покажет ссылку на подписку и QR-код — их и отправьте
   человеку. По ссылке откроется страница с приложениями для его устройства.

Вручную: скопируйте `.env.example` в `.env`, заполните и выполните `docker compose up -d`.

### Варианты установки

- **Один сервер.** Ответьте «да» на вопрос про мост — сервер будет и панелью, и VPN, трафик выходит
  с его IP. Выходную ноду можно добавить позже: мост сам перейдёт на каскад.
- **Панель и мост на одном сервере, выходные ноды отдельно.** Порт 443 занимает Xray, а браузеры и
  агенты нод Reality передаёт панели, поэтому снаружи сервер выглядит как обычный сайт с настоящим
  сертификатом.
- **Панель отдельно.** Надёжнее всего: на сервере панели база всех пользователей, а IP мостов
  известны всем клиентам.

## Приложения

Ссылка на подписку одна, формат подбирается под приложение автоматически.

| Приложение | Формат подписки | Что получает |
|---|---|---|
| [Karing](https://karing.app) | sing-box JSON | все варианты, включая mieru; сам выбирает лучший сервер |
| [Happ](https://www.happ.su), [Hiddify](https://hiddify.com), v2rayNG, NekoBox и др. | список ссылок | VLESS, XHTTP, Hysteria2, CDN — что поддерживает приложение |
| [mihomo](https://github.com/MetaCubeX/mihomo) (в т.ч. на роутере), Throne | список ссылок | то же плюс mieru |

Приложения на странице подписки, название профиля и ссылку «Помощь» можно поменять в разделе
«Страница подписки».

## Протоколы

Включаются в разделе «Протоколы», изменения доходят до нод за минуту.

| Протокол | Порт | Когда нужен |
|---|---|---|
| **VLESS + Reality** (TCP, XTLS Vision) | TCP 443 | основной: выглядит как HTTPS к настоящему сайту |
| **XHTTP** | TCP 443 | запасной на том же порту, если основной начнут резать |
| **Hysteria2** | UDP 443 | быстрый на каналах с потерями; иногда UDP режут сильнее |
| **mieru** | TCP 40100–40109 | без TLS, трафик похож на шум — на случай, если начнут резать TLS и QUIC |
| **Через CDN** | TCP 8443 | если IP ноды заблокирован: подключение идёт через Cloudflare |

Пользователи, квоты, статистика и маршрутизация работают одинаково для всех протоколов.
Нодам, установленным из панели, нужные порты открываются в ufw автоматически.

<details>
<summary><b>Подробнее о каждом протоколе</b></summary>

**SNI (маскировка Reality).** Каждая нода выдаёт себя за настоящий сайт — он должен открываться с
самой ноды по TLS 1.3 и HTTP/2. Агент проверяет это сам; если сайт не подходит, у ноды в панели
горит `SNI ✗` с причиной. SNI меняется кнопкой ✏️ без переустановки. Проверить кандидата с ноды:
`curl -so /dev/null --tlsv1.3 --http2 -w '%{http_version}\n' https://example.com` (нужно `2`).

**Отпечаток TLS** («Маршрутизация») — под какой браузер маскируются подключения: chrome (по
умолчанию), firefox, safari, ios, android, edge, random. Если соединения вдруг начали «замирать»
везде сразу, попробуйте сменить.

**Hysteria2.** Сертификат самоподписанный, нода выпускает его сама; приложения проверяют его по
отпечатку, поэтому домен не нужен, а подменить сервер нельзя. Опция **Salamander** делает пакеты
похожими на шум, но работает только в приложениях с её поддержкой (Karing, Hiddify, v2rayNG, mihomo).
На сервере «панель + мост» откройте UDP 443 сами, если там включён фаервол.

**mieru.** Агент сам ставит сервер mieru (`mita`) из официального релиза со сверкой контрольной суммы
и передаёт ему пользователей панели. Новые пользователи добавляются без обрыва соединений.

**Через CDN.** Для каждой ноды, которую нужно сделать доступной через Cloudflare:
1. A-запись (например, `cdn.example.com`) на IP ноды с включённым проксированием (оранжевое облако).
2. SSL/TLS → режим **Full** (не «Flexible» и не «Full (strict)»).
3. Домен — в карточку ноды, строка CDN.

Через CDN медленнее, чем напрямую, — это запасной путь. Если не подключается, проверьте режим
«Full» и выключите Bot Fight Mode. Связь моста с выходной нодой тоже можно пустить через CDN —
на случай, когда режут канал до зарубежного хостера.

**Связь мост → выходная нода** («Маршрутизация»): TCP + Vision по умолчанию или XHTTP, который
пускает много соединений пользователей через одно — сайты открываются быстрее.
</details>

## Маршрутизация

Раздел «Маршрутизация»:

- **Страна** (Россия, Иран, Китай) — готовые правила для местных сайтов. Их трафик можно отправить
  через WARP, напрямую с моста или через выходную ноду. Ещё лучше, когда местный трафик вообще не
  попадает в VPN: для этого в приложении выбирают регион (например, Hiddify → Регион).
- **Через WARP** — сервисы, которые не любят IP хостингов (готовые шаблоны: Google, OpenAI, Netflix,
  Spotify). WARP ставится на выходные ноды автоматически.
- **Напрямую с мостов** — что мост выпускает сам, минуя выходные ноды.
- **Прямые ссылки на выходные ноды** — подключение без моста (меньше пинг), но пользователи видят
  IP выходной ноды.

Правила пишутся так: `geosite:`, `geoip:`, `domain:`, `full:`, `keyword:`, IP или подсеть.

## Пользователи и подписки

У каждого пользователя есть квота, срок и ссылка на подписку `https://<домен>/sub/<токен>`.
Приложения сами показывают остаток трафика и срок. Если ссылка утекла, кнопкой ✏️ можно выдать новую
ссылку или новый ключ. Новые пользователи добавляются на ноды без перезапуска и обрыва соединений.

Если открыть ссылку в браузере, пользователь увидит свою страницу: трафик, срок, приложения для его
устройства с кнопками «Скачать» и «Добавить» (подписка вставляется в приложение сама) и QR-код.

Серверы в приложениях называются «KVN <адрес>»; понятную подпись вроде «🇳🇱 Амстердам» задайте
кнопкой с ярлыком на карточке ноды.

<details>
<summary><b>Переезд с другой панели</b></summary>

**📥 Импорт** на странице пользователей — по строке на человека: имя, токен или старая ссылка
подписки целиком, по желанию квота в ГБ и срок. Если хоть в одной строке ошибка, не импортируется
никто.
```
alice 57d2bfa5b82efcc2d127dd64f5dce8c7
bob   https://old.example.com/sub/0a1b2c3d4e5f60718293a4b5c6d7e8f9  50  2026-12-31
```
Старые ссылки вида `https://<старый-домен>/sub/<токен>` продолжат работать:
1. Поставьте панель на новом домене и импортируйте пользователей.
2. Проверьте на своём телефоне подписку `https://<новый-домен>/sub/<старый-токен>`.
3. Добавьте старый домен вторым сайтом: в `/opt/kvn-panel/Caddyfile` замените `{$DOMAIN} {` на
   `{$DOMAIN}, old.example.com {`, выполните `docker compose restart caddy` и направьте DNS старого
   домена на новый сервер. `DOMAIN` в `.env` не меняйте.
</details>

## Мониторинг и уведомления

- **Серверы.** На карточке каждой ноды — CPU, память, диск, сеть, число соединений и время работы,
  а также графики за сутки и неделю. Два показателя помогают понять, чья проблема, когда тормозит
  всё сразу: **steal** (процессор забирают соседи — хостер перегрузил машину) и **TCP-ретрансмиты**
  (потери в сети хостера).
- **Канал мост → выходная нода.** Мост раз в минуту проверяет задержку и потери до каждой выходной
  ноды. Графики показывают, в какие часы канал проседает, — готовые цифры для обращения к хостеру.
- **Telegram.** «Настройки» → «Уведомления в Telegram»: токен бота от @BotFather и ваш ID чата
  (подскажет @userinfobot). Бот пишет о проблемах с нодами, ошибках обновлений, деградации канала,
  перегрузке серверов и о том, что у пользователя кончается трафик или подписка — и отдельно, когда
  всё исправилось. Сообщения отправляет выходная нода, поэтому они доходят, даже если Telegram
  заблокирован там, где стоит панель.

## Безопасность

- **Скрытая панель.** Панель открывается по секретному пути `https://<домен>/<ADMIN_PATH>/` — его
  генерирует установщик. На главной странице — нейтральная заглушка (или ваш сайт из
  `/opt/kvn-panel/data/site`), всё остальное отвечает 404.
- **Двухфакторный вход.** Код из Google Authenticator, Aegis, 2FAS, Bitwarden и т.п. плюс 8
  резервных кодов. Потеряли и телефон, и коды:
  `cd /opt/kvn-panel && docker compose exec master ./kvn-master reset-2fa`.
- **Ноды.** У каждой свой токен (в базе — только хэш) и свой ключ Reality, который есть только на
  самой ноде.
- **SSH.** У панели свой SSH-ключ, ноды сами добавляют его в `authorized_keys` (в отдельный блок,
  не трогая остальное). Свои ключи можно добавить в «Настройки» → «SSH-ключи». На карточке ноды:
  - **терминал** `>_` — root-консоль в браузере. Работает, даже если упал агент. Нужен двухфакторный
    вход и свежий код на каждую сессию; входы пишутся в журнал и приходят в Telegram;
  - **«Выключить вход по паролю»** — панель сначала проверяет, что её ключ работает, и только потом
    выключает пароль;
  - **переустановка** без пароля, по ключу панели.
- **Действия** (кнопка ⏻): перезапуск Xray, mieru или агента и перезагрузка сервера.

Это не средство анонимности уровня Tor: мост знает, к каким адресам вы подключаетесь, а выходная нода
— откуда пришёл трафик. Серверы, база и логи — под вашей ответственностью.

## Обновления

Панель: `cd /opt/kvn-panel && docker compose pull && docker compose up -d`.

Ноды обновляются сами, каждый шаг с проверкой — если что-то не так, остаётся рабочая версия,
а в панели видна причина:
- **агент** подтягивается к версии панели в течение минуты после её обновления;
- **Xray** — до версии, заданной в «Настройки» → «Обновления» (кнопка «Узнать последнюю»);
- **геобазы** ([Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat)) — каждую ночь.

## Бэкап и восстановление

Панель каждый день сохраняет копию базы в `/opt/kvn-panel/data/backups` (7 последних). Свежую
копию можно скачать кнопкой «💾 Бэкап» — храните её не на том же сервере, вместе с файлом
`/opt/kvn-panel/.env`. Ключи нод в базе не хранятся, поэтому после восстановления ноды работают
без переустановки.

```bash
cd /opt/kvn-panel
docker compose stop master
cp /путь/к/kvn-backup-….sqlite data/db.sqlite
docker compose start master
```

## Если что-то не работает

- **Нода не появилась после установки** — причина видна в её карточке («Деплой не удался: …»).
  Частые: неверный пароль, закрыт SSH, на сервере не Debian/Ubuntu. Кнопка 🔄 повторяет установку.
- **`SNI ✗` у ноды** — сайт маскировки не открывается с неё; выберите другой (кнопка ✏️).
- **`WARP ✗`** — WARP не поднялся, трафик «через WARP» идёт с IP ноды. Часто это временно.
- **Не подключается через CDN** — проверьте режим SSL «Full» и выключите Bot Fight Mode.
- **Двухфакторный код не подходит** — проверьте время на сервере (`timedatectl`); панель сама скажет,
  если часы ушли.

## Разработка

```bash
go test ./...
cd frontend && npm ci && npm run dev   # проксирует /api на localhost:8080
```

| Часть | Что внутри |
|---|---|
| `cmd/master` | API и панель: Go, [Echo](https://echo.labstack.com/), [GORM](https://gorm.io/) + SQLite |
| `frontend` | [Vue 3](https://vuejs.org/), [Vite](https://vite.dev/), [Tailwind CSS](https://tailwindcss.com/) |
| `cmd/agent` | агент на нодах: раз в минуту берёт конфиг у панели, собирает и проверяет конфиг Xray, присылает статистику |
| `internal/protocol` | формат обмена панель ↔ агент |
| `ansible/` | установка ноды по IP и паролю |

VPN-ядро — [Xray-core](https://github.com/XTLS/Xray-core), сервер mieru — [mita](https://github.com/enfein/mieru),
веб-сервер — [Caddy](https://caddyserver.com/). CI публикует образ
`ghcr.io/sud0-i/kvn-bridge-panel:latest` при каждом пуше в `main`.

Ошибки и предложения — в [Issues](https://github.com/sud0-i/KVN-Bridge-Panel/issues).
