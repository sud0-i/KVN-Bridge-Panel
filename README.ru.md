# KVN-Bridge-Panel

[English](README.md) · **Русский**

Self-hosted панель для личного VPN на собственных серверах: для себя и нескольких
близких людей. Трафик шифруется от устройства до ваших серверов, поэтому ни публичный
Wi-Fi, ни провайдер не видят, какие сайты вы открываете. Вход и выход разнесены
по разным серверам.

```
устройство ──VLESS+Reality──▶ мост ──VLESS+Reality──▶ выходная нода ──▶ интернет
     └──────────── прямая ссылка (по желанию) ─────────────┘   └─▶ Cloudflare WARP (по правилам)
```

- **Мост** — точка входа: к нему подключаются устройства пользователей.
- **Выходная нода** — сервер, от имени которого трафик уходит в интернет. Если нод
  несколько, мост распределяет трафик между ними и постоянно проверяет, что каждая
  действительно выпускает в интернет. Нода считается упавшей, только если провалились все
  проверки за последние ~2 минуты: единичный обрыв её не выключает, а упавшая сама выпадает
  из ротации. Если лежат
  все выходные ноды, мост блокирует трафик, а не выпускает его со своего IP. Чтобы вернуться
  в [одиночный режим](#одиночный-сервер), удалите выходные ноды в панели.
- **Мастер** — панель управления: пользователи, серверы, маршрутизация, подписки, статистика.

Панель и страница подписки есть на русском и английском.

## Маршрутизация
Настраивается в разделе «Маршрутизация», изменения доходят до нод за минуту.

- **Страна** (Россия, Иран, Китай) — подставляет готовые правила `geosite:`/`geoip:`.
  Её трафик, если он попал в туннель, можно отправить:
  - **через WARP на выходной ноде** — сайты видят IP Cloudflare, а не вашей ноды;
  - **напрямую с моста** — сайты видят IP моста;
  - **через выходную ноду**, как весь остальной трафик.

  Лучше всего, когда местный трафик вообще не заходит в VPN: пользователю достаточно
  выбрать регион в клиенте (например, Hiddify → Регион).
- **Через WARP** — свои правила и шаблоны (Google, OpenAI, Netflix, Spotify) для сервисов,
  которые не любят IP хостингов.
- **Напрямую с мостов** — что мосты выпускают сами, минуя выходные ноды.
- **Прямые ссылки на выходные ноды** — в подписке появляются серверы «KVN direct»
  для подключения без моста (меньше пинг). Пользователи при этом видят IP выходных нод.

- **Связь мост → выходная нода** — TCP + Vision (по умолчанию) на каждое соединение пользователя
  открывает к ноде новое соединение с рукопожатием Reality. **XHTTP** пускает десятки потоков через
  одно соединение: сайты открываются быстрее примерно на два пинга мост ↔ нода, а DPI не видит
  потока коротких TLS-соединений. Нужна включённая настройка XHTTP.
- **Отпечаток TLS (fingerprint)** — под какой браузер маскируются подключения (по умолчанию chrome;
  также firefox, safari, ios, android, edge, qq, random). Действует и в подписках пользователей, и на
  участке мост → выходная нода. Если соединения вдруг начинают «замирать» везде сразу, возможно, DPI
  начал душить конкретный отпечаток — смените его.

Правила: `geosite:`, `geoip:`, `domain:`, `full:`, `keyword:`, IP или подсеть.

WARP (официальный клиент Cloudflare в режиме прокси на `127.0.0.1:40000`) ставится
на выходные ноды при деплое, а на одиночный сервер — если выбрать это в установщике. Если на
ноде он не поднялся, «WARP-трафик» уходит с IP ноды, а в панели у неё виден значок `WARP ✗`.

### Запасной транспорт XHTTP
Кроме основного подключения (VLESS + Reality + XTLS Vision поверх TCP) каждая нода
принимает XHTTP на **том же порту 443**: подключение проходит Reality, а затем Xray
передаёт его на внутренний XHTTP-вход. В подписке у каждого сервера есть вариант
«XHTTP» — если основной начнут резать, достаточно переключиться на него в клиенте.
Выключается в разделе «Протоколы».

### Hysteria2
Второй протокол рядом с VLESS, включается переключателем в разделе **«Протоколы»**. На каждой ноде
появляется вход Hysteria2 на **UDP 443** (рядом с TCP 443 Reality) внутри того же Xray, поэтому
пользователи, квоты, статистика трафика, каскад и маршрутизация работают так же. В подписке
появляются серверы «Hy2» (ссылки `hysteria2://` и outbound'ы в sing-box JSON для Karing).

- Сертификат самоподписанный, агент выпускает его сам на SNI ноды. Приложения проверяют его по
  отпечатку (`pinSHA256`, а sing-box — по сертификату целиком), поэтому домен нодам не нужен,
  а подменить сервер нельзя.
- **Salamander** (по желанию) делает пакеты похожими на случайный шум, а не на HTTP/3. Помогает, где
  режут QUIC, но работает только в приложениях с его поддержкой (Karing, Hiddify, v2rayNG, mihomo).
- Работает по UDP: иногда быстрее TCP, но у некоторых операторов UDP душат сильнее — сравнивайте.
- Нодам, развёрнутым из панели, UDP 443 открывается в ufw. На сервере «мастер + мост» откройте его
  сами, если там включён фаервол.

### mieru
Запасной протокол без TLS: трафик похож на шум, а не на HTTPS. Пригодится, если начнут резать TLS
и QUIC, на которых держатся остальные протоколы. Включается в разделе «Протоколы».

Агент сам ставит сервер mieru (`mita`) из релиза на GitHub со сверкой контрольной суммы, открывает
порты (по умолчанию TCP 40100–40109, клиент перескакивает по ним) и передаёт в него тех же
пользователей, что в панели. Новые пользователи добавляются без обрыва соединений, блокировка и
удаление — перезапуском mita. Трафик mita выходит через локальный вход Xray, поэтому каскад через мост,
WARP, правила маршрутизации, статистика и лимиты работают так же, как у остальных протоколов.

Сервер «… mieru» появляется в подписке, когда нода сообщила, что mita работает: в JSON для Karing и
ссылкой `mierus://` в обычной подписке — её понимают mihomo (в том числе на роутере), Throne и клиент
mieru. Приложения без mieru (v2rayNG, Hiddify и т.п.) такую строку пропускают. Ошибки установки видны
в карточке ноды.

### Через CDN
Запасной путь на случай, когда IP ноды заблокирован или канал до неё режут: подключение идёт через
CDN (Cloudflare и т.п.), а не напрямую. Включается в разделе «Протоколы». Затем для каждой ноды:
1. В Cloudflare — A-запись (например, `cdn.example.com`) на IP ноды с оранжевым облаком (проксирование).
2. SSL/TLS → режим **Full**. Не «Flexible» (нода ждёт TLS) и не «Full (strict)» (сертификат ноды
   самоподписанный).
3. Домен — в карточку ноды, строка CDN.

Нода поднимает вход XHTTP поверх TLS на порту **8443** (его Cloudflare проксирует, а 443 занят Reality)
и сама открывает порт в ufw. В подписке появляются серверы «… CDN»: TLS до CDN с его настоящим
сертификатом, XHTTP в режиме `packet-up`, который проходит через любой CDN. У выходных нод вариант
через CDN появляется и без прямых ссылок: IP ноды клиент не видит. Связь моста с выходной нодой тоже
можно пустить через CDN («Связь моста → выходная нода» → «XHTTP через CDN») — на случай, когда режут
канал из РФ до зарубежного хостера. Если у экзита нет CDN-домена, мост ходит к нему как через XHTTP.

Через CDN медленнее и с большей задержкой, чем напрямую, — это запасной путь, а не основной. Если не
подключается, проверьте SSL-режим «Full» и выключите Bot Fight Mode для домена.

### SNI
Reality маскирует каждую ноду под настоящий сайт (SNI): нода при каждом подключении
обращается к нему, поэтому сайт должен **открываться с самой ноды** по TLS 1.3 и HTTP/2.
Агент проверяет это сам — если нет, в панели у ноды горит `SNI ✗` с причиной.
SNI задаётся при деплое и меняется кнопкой ✏️ без переустановки; подписки обновятся сами.
Проверить кандидата вручную можно с ноды:
`curl -so /dev/null --tlsv1.3 --http2 -w '%{http_version}\n' https://example.com` (нужно `2`).

### Чего здесь нет
Это не средство анонимности уровня Tor: мост видит, к каким адресам вы подключаетесь,
а выходная нода — откуда пришёл трафик моста. Серверы, база и логи — под вашей
ответственностью: защищайте доступ к ним.

## Стек технологий
| Часть | Технологии |
|---|---|
| VPN-ядро | [Xray-core](https://github.com/XTLS/Xray-core): VLESS, Reality, XTLS Vision, XHTTP; geosite/geoip от [Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat) |
| Мастер (бэкенд) | Go, [Echo](https://echo.labstack.com/), [GORM](https://gorm.io/) + SQLite, JWT, [go-qrcode](https://github.com/skip2/go-qrcode) |
| Панель (фронтенд) | [Vue 3](https://vuejs.org/), [Vite](https://vite.dev/), [Tailwind CSS](https://tailwindcss.com/) |
| Агент на нодах | Go, gRPC StatsService Xray для трафика по пользователям, systemd |
| WARP | Официальный клиент [Cloudflare WARP](https://developers.cloudflare.com/warp-client/) в режиме прокси |
| Веб-сервер и TLS | [Caddy](https://caddyserver.com/): автоматический HTTPS, PROXY protocol в режиме «мастер + мост» |
| Развёртывание | Docker Compose, [Ansible](https://www.ansible.com/) (деплой нод по IP и паролю), установщик на bash |
| CI | GitHub Actions: `go vet`, тесты с `-race`, сборка фронтенда, shellcheck, тест установщика, публикация образа в GHCR |

## Компоненты
- `cmd/master` — API и панель (Echo + SQLite), раздаёт Vue-фронтенд и подписки `/sub/<token>`.
- `cmd/agent` — агент на каждой ноде: раз в минуту берёт с Мастера `/api/sync`,
  собирает `config.json` для Xray (`internal/xray`), проверяет его `xray run -test`
  и перезапускает Xray только при изменениях; отправляет статистику трафика
  и сообщает состояние ноды (WARP, ошибки конфига).
- `internal/protocol` — формат обмена Мастер ↔ Агент, не привязан к конкретному ядру.
- `ansible/deploy_node.yml` — авто-деплой ноды по IP и root-паролю.

Каждая нода получает собственный токен (в БД хранится только его sha256)
и собственный приватный ключ Reality, который есть только на самой ноде.

## Установка
```bash
curl -fsSL https://raw.githubusercontent.com/sud0-i/KVN-Bridge-Panel/main/install.sh | sudo bash
```
Перед запуском направьте A-запись домена на сервер. Установщик спросит домен, пароль
и нужно ли сделать этот же сервер мостом.

Или вручную: скопируйте `.env.example` в `.env`, заполните и выполните `docker compose up -d`.
Для деплоя нод Мастер должен быть доступен по `https://$DOMAIN` (или задайте `MASTER_URL`).

### Скрытая панель
Панель открывается по секретному пути: `https://<домен>/<ADMIN_PATH>/`. Путь генерирует установщик
и выводит адрес в конце, он хранится в `ADMIN_PATH` в `/opt/kvn-panel/.env`. По `https://<домен>`
открывается нейтральная заглушка, а всё остальное отвечает обычной 404, в том числе `/api/login`,
неизвестные токены подписки и запросы агентов без токена ноды. Чтобы вместо заглушки был свой сайт,
положите его (с `index.html`) в `/opt/kvn-panel/data/site`.

Для уже установленного мастера добавьте в `.env` строку `ADMIN_PATH=<8–64 символа: латиница, цифры,
- или _>` и выполните `docker compose up -d`. Без `ADMIN_PATH` панель остаётся в корне сайта, как раньше.

### Мастер и мост на одном сервере
Порт 443 занимает Xray. Подключения, которые не являются VPN-клиентами (браузер,
агенты других нод, сканеры), Reality пересылает в локальный Caddy (`127.0.0.1:8443`,
см. `Caddyfile.combined`) вместе с настоящим IP через PROXY protocol. Снаружи сервер
выглядит как обычный сайт с настоящим сертификатом, а панель открывается по тому же домену.

Режим удобен для старта. Для постоянной работы Мастер лучше вынести на отдельный сервер:
на нём база всех пользователей, а IP моста известен всем клиентам.

### Одиночный сервер
Самый простой вариант — один сервер и больше ничего: запустите установщик и ответьте «да» на вопрос
про мост. Без выходных нод мост сам выпускает трафик в интернет:
```
устройство ──VLESS+Reality──▶ сервер (мастер + мост) ──▶ интернет
```
Всё остальное работает как обычно: подписки, страница пользователя, XHTTP, квоты, бэкапы, скрытая
панель. Установщик предложит поставить Cloudflare WARP. Если он стоит, правила «через WARP» и
настройку страны выполняет сам сервер; без WARP этот трафик идёт с IP сервера. Выходную ноду можно
добавить позже в разделе **Ноды** — когда она выйдет на связь, мост сам перейдёт на каскад,
переустанавливать ничего не нужно. Пока нода не выходила на связь (деплой идёт или упал), одиночный
режим продолжает работать.

### Сетевой тюнинг
При деплое каждая нода получает BBR, очередь `fq`, увеличенные буферы TCP и MTU probing
(`/etc/sysctl.d/99-kvn-network.conf`). Это заметно ускоряет длинные маршруты с потерями.
В контейнерах (OpenVZ, LXC) часть параметров может не примениться, деплой при этом не падает.

## Пользователи и подписки
У каждого пользователя есть ссылка на подписку `https://<домен>/sub/<токен>`. Кнопка 🔗 показывает её
вместе с QR-кодом для телефона. Кнопкой ✏️ меняются квота, срок и лимит IP. Там же можно сбросить трафик
и выдать новую ссылку или новый ключ (например, если ссылка утекла). Клиенты получают название профиля,
интервал обновления (12 ч), трафик и срок через стандартные заголовки `subscription-userinfo`.

Новый пользователь появляется на нодах без перезапуска Xray: агент добавляет его через API Xray,
и соединения остальных не рвутся. Блокировка, удаление, смена ключа и изменения настроек
применяются перезапуском (на секунду). Иначе уже открытые соединения заблокированного пользователя
продолжали бы работать. Перед перезапуском агент забирает накопленный трафик, так что статистика
не теряется.

### Страница подписки
Если открыть ссылку в браузере, пользователь увидит свою страницу: трафик и срок, приложения для его
устройства (определяется само) с кнопками **Скачать** и **Добавить**, QR-код для другого устройства
и ссылку для помощи. **Добавить** — это deeplink: приложение откроется с уже вставленной подпиской.
По умолчанию там Karing, Happ и Hiddify. Список, название профиля и ссылку для помощи можно поменять
в разделе **«Страница подписки»**.

VPN-приложения получают подписку в понятном им формате. Karing и официальные приложения sing-box
получают sing-box JSON: старая панель RIXX тоже отдавала Karing JSON, так что у перенесённых профилей
формат не меняется. Варианты XHTTP уходят только в Karing, обычный sing-box XHTTP не умеет. Выбирать самый
быстрый сервер Karing умеет сам, встроенным автовыбором. Все остальные приложения (Happ, Hiddify,
v2rayNG, NekoBox, Throne и другие) получают стандартный base64-список ссылок `vless://`. Формат можно
задать вручную: `?format=singbox` или `?format=base64`.

Серверы называются «KVN <адрес>». Чтобы в приложениях было понятнее, например «🇳🇱 Амстердам»,
задайте подпись кнопкой с ярлыком на карточке ноды в разделе **Ноды**.

### Переезд с другой панели
Пользователей можно перенести вместе со старыми ссылками. Нажмите **📥 Импорт** и вставьте по строке
на пользователя:
```
alice 57d2bfa5b82efcc2d127dd64f5dce8c7
bob   https://old.example.com/sub/0a1b2c3d4e5f60718293a4b5c6d7e8f9  50  2026-12-31
```
В строке указываются имя, токен или старая ссылка целиком, а по желанию ещё квота в ГБ и срок.
Если хоть в одной строке ошибка, не импортируется никто.

Старые ссылки продолжат работать, если они имеют вид `https://<старый-домен>/sub/<токен>`:
1. Поднимите новый мастер на своём домене и импортируйте пользователей.
2. Проверьте на своём телефоне: добавьте подписку `https://<новый-домен>/sub/<старый-токен>`.
   Ровно это пользователи получат после переключения.
3. При переключении `DOMAIN` не меняйте: к нему привязаны ноды и клиенты. Просто добавьте старый
   домен вторым сайтом: в `/opt/kvn-panel/Caddyfile` замените строку `{$DOMAIN} {` на
   `{$DOMAIN}, old.example.com {`, выполните `docker compose restart caddy` и направьте DNS старого
   домена на новый сервер. Caddy получит сертификат за минуту. При следующем обновлении клиент
   получит новые серверы.

## Уведомления в Telegram
«Настройки» → «Уведомления в Telegram»: токен бота от @BotFather и ID чата (его подскажет @userinfobot;
сначала напишите своему боту /start). Бот сообщает:
- **ноды**: пропала и вернулась, конфиг не применён, сайт маскировки или WARP не работают;
- **обновления**: не удалось обновить агент, Xray или геобазы;
- **пользователи**: 90% и 100% трафика, подписка заканчивается через 3 дня и закончилась.

Мастер раз в минуту сравнивает текущее состояние с тем, о чём уже сообщал: об одной проблеме бот пишет
один раз, а когда её исправят — отдельным сообщением. С российского моста Telegram недоступен, поэтому
сообщения отправляет выходная нода при синхронизации и подтверждает доставку мастеру. Если ответа
нет, сообщение уходит повторно, после пяти попыток считается недоставленным. Без выходных нод
(одиночный сервер) мастер отправляет сам. Токен в панель обратно не показывается. Кнопка
«Отправить тест» проверяет всю цепочку, итог виден там же. Свой Bot API (локальный сервер
или зеркало) задаётся переменной `TELEGRAM_API` у мастера и агентов.

## Качество канала мост → выходная нода
Мост раз в минуту делает 10 TCP-подключений к 443 каждой выходной ноды — туда же, куда идёт
трафик пользователей. Задержка — время ответа, потери — подключения без ответа за секунду. ICMP
(`ping`) для этого не годится: по дороге его часто режут или обрабатывают в последнюю очередь.

В разделе «Ноды» — графики задержки и потерь за сутки (по 10 минут) и за неделю (по часам). Так видно,
в какие часы канал проседает, и это готовые цифры для обращения к хостеру. На «Обзоре» у выходной
ноды — текущие задержка и потери. Если потери за 10 минут превышают 10%, пункт появляется в «Требует
внимания», а бот в Telegram пишет о проблеме и потом о восстановлении. Замеры хранятся 8 дней.

## Показатели серверов и управление
Агенты присылают показатели серверов раз в минуту, в разделе «Ноды» они видны на карточке каждой ноды:
CPU, память, диск, сеть, число TCP-соединений, время работы. Там же графики за сутки и неделю.
Два показателя помогают понять, чья проблема, когда тормозит всё сразу:
- **steal** — сколько процессора забирают соседи по физическому серверу. Высокий steal значит, что
  хостер перегрузил машину;
- **TCP-ретрансмиты** — какая доля пакетов уходит повторно. Это потери в сети, как их видит сам сервер.

Уведомления в Telegram приходят, когда диск заполнен на 90%, память — на 95%, CPU выше 90% или steal
выше 20% десять минут подряд, а также когда ретрансмиты превышают 5%. Замеры хранятся 8 дней.

Кнопка ⏻ на карточке ноды перезапускает Xray, mieru или агент либо перезагружает сервер. Команда
уходит при следующей синхронизации (до минуты), а итог виден на карточке. Если нода не выходила на
связь 5 минут, команда отменяется: перезагрузка не случится внезапно через час.

## Двухфакторный вход
«Настройки» → «Двухфакторный вход»: QR-код для Google Authenticator, Aegis, 2FAS, Bitwarden и т.п.
Код считается в телефоне по времени, интернет для этого не нужен. После включения панель выдаёт
8 одноразовых резервных кодов на случай потери телефона. Если потеряны и телефон, и коды, выключите
2FA на сервере мастера:
```bash
cd /opt/kvn-panel && docker compose exec master ./kvn-master reset-2fa
```
Коды зависят от времени, поэтому часы сервера должны быть точными (`timedatectl`). Если они ушли,
панель так и скажет, а не просто «неверный код».

## Терминал и SSH
У мастера свой SSH-ключ (`/opt/kvn-panel/data/ssh/id_ed25519`, создаётся при первом запуске).
Агенты сами ставят его публичную часть в `/root/.ssh/authorized_keys` — в отдельный блок
`# kvn-panel`, остальные строки файла не трогаются. В «Настройки» → «SSH-ключи» можно добавить
свои ключи: они попадут на все ноды.

- **Терминал.** Кнопка `>_` на карточке ноды открывает root-консоль прямо в панели:
  браузер → WebSocket → мастер → SSH на ноду. От агента не зависит — работает, даже если агент
  или Xray упали. Нужен включённый двухфакторный вход и свежий код на каждую сессию; сессия
  закрывается после 15 минут без ввода. Входы пишутся в журнал («Настройки» → «SSH-ключи»)
  и, если включены уведомления, приходят в Telegram.
- **Копирование и вставка.** Выделение текста копирует его; вставка — Ctrl+V, Ctrl+Shift+V или
  правая кнопка мыши. На телефоне — кнопка «Вставить», клавиши Esc, Tab, Ctrl, стрелки и строка
  ввода с кнопкой «Отправить». Буфер обмена браузер даёт только по HTTPS.
- **Вход только по ключу.** В строке «SSH» на карточке ноды — «Выключить вход по паролю».
  Мастер сначала проверяет, что его ключ пускают, и только потом агент кладёт
  `/etc/ssh/sshd_config.d/00-kvn.conf` (`PasswordAuthentication no`), проверяет его `sshd -t`
  и перезагружает sshd. Вернуть пароль — той же кнопкой.
- **Переустановка без пароля.** Если ключ мастера уже стоит, поле пароля при переустановке можно
  оставить пустым. Пароль нужен, только если ОС на сервере переустанавливали.
- Ключ SSH-сервера ноды запоминается при первом входе. Если он сменился (переустановили ОС),
  терминал откажет — переустановите ноду с паролем, это сбросит запомненный ключ.

## Обновления
Мастер обновляется образом: `cd /opt/kvn-panel && docker compose pull && docker compose up -d`.
Остальное ноды обновляют сами, каждый шаг с проверкой. Если проверка не прошла, остаётся то,
что работало, а у ноды в панели появляется «Ошибка обновления» с причиной.

- **Агент.** Ноды сверяют свой бинарник с тем, что лежит в образе мастера. Если он другой,
  нода скачивает новый (по своему токену), сверяет SHA-256 и перезапускается в нём.
  Так ноды подтягиваются к мастеру в течение минуты после его обновления.
- **Xray.** Версия задаётся в панели («Настройки» → «Обновления»). Кнопка «Узнать последнюю»
  спрашивает GitHub. Нода скачивает релиз, сверяет его с `.dgst` и проверяет на новой версии
  текущий конфиг (`xray run -test`). Только после этого она подменяет бинарник и перезапускает Xray.
  Пустое поле — версией не управлять. Hysteria2 нужен Xray 26.3.27 или новее: более старую
  версию с включённым Hysteria2 нода не поставит.
- **Геобазы.** geoip.dat и geosite.dat от [Loyalsoldier](https://github.com/Loyalsoldier/v2ray-rules-dat)
  обновляются раз в сутки, с 3 до 6 утра по времени сервера. Базы старше трёх суток обновляются сразу.
  Контрольные суммы сверяются, Xray перезапускается, только если базы изменились.

В таблице нод видны версия Xray, агента (жёлтая — ждёт обновления) и дата геобаз.
Отключить самообновление агента на ноде: `AGENT_SELF_UPDATE=0` в `/etc/vpn-agent/.env`.

**Один раз при переходе на эту версию** агенты ещё не умеют обновляться сами. После обновления мастера:
- мост на сервере мастера:
  `cd /opt/kvn-panel && docker compose cp master:/app/build/agent_linux_amd64 /usr/local/bin/vpn-agent && systemctl restart vpn-agent`;
- остальные ноды: кнопка 🔄 в панели.

## Бэкап и восстановление
Мастер раз в сутки кладёт копию базы в `/opt/kvn-panel/data/backups` и хранит 7 последних.
Свежую копию можно скачать кнопкой «💾 Бэкап» в панели — храните её не на том же сервере.

В базе пользователи, ноды (с хэшами токенов и публичными ключами) и настройки.
Приватные ключи нод лежат только на самих нодах, поэтому после восстановления
ноды продолжают работать без переустановки. Отдельно сохраните `/opt/kvn-panel/.env`
(пароль администратора и секрет JWT).

Восстановление:
```bash
cd /opt/kvn-panel
docker compose stop master
cp /путь/к/kvn-backup-….sqlite data/db.sqlite
docker compose start master
```
